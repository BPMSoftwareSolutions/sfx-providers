The cleanest way to sketch a **SideFX capability circuit** is to keep the geometry consistent: the canonical blueprint is a typed semantic graph, and each altitude preserves the three-position cell pattern. Authority expands downward from meaning toward physical execution; evidence contracts back upward toward the promised experience. :chatgpt-content-reference{index="0"}

### 1. The irreducible capability cell

```text
                 CAPABILITY / SCENARIO

        ┌─────────────────────────────┐
        │                             │
        │          INPUT              │
        │      admitted state         │
        │             │               │
        │             ▼               │
        │          EVENT              │
        │   bounded responsibility    │
        │             │               │
        │             ▼               │
        │         OUTCOME             │
        │    promised experience      │
        │                             │
        └─────────────────────────────┘
```

Semantically:

```text
GIVEN                WHEN                 THEN

INPUT        ──────► EVENT       ──────► OUTCOME
DATA                  ACTION               EXPERIENCE
```

That is the basic transistor.

### 2. Open the event and descend one altitude

The scenario says **what must happen**.

Opening the event reveals **how responsibility closes**:

```text
SCENARIO CELL
─────────────────────────────────────────

┌────────────┐
│   INPUT    │
└─────┬──────┘
      │
      ▼
┌────────────┐
│   EVENT    │
└─────┬──────┘
      │
      │ expand authority
      ▼
      ┌─────────────────────────────┐
      │      EXECUTION CELL         │
      │                             │
      │   Input                     │
      │     │                       │
      │     ▼                       │
      │   Responsibility            │
      │     │                       │
      │     ▼                       │
      │   Result                    │
      └─────────────┬───────────────┘
                    │
                    ▼
┌────────────┐
│  OUTCOME   │
└────────────┘
```

And it keeps going:

```text
SCENARIO
Input → Event → Outcome
          │
          ▼
EXECUTION
Input → Responsibility → Result
          │
          ▼
MECHANIC
Input → Mechanic → Result
          │
          ▼
PROVIDER
Physical Input → Native Operation → Physical Result
```

That exact fractal structure is part of the accepted blueprint model. :chatgpt-content-reference{index="1"}

### 4. Branching capability circuit

A proper capability isn't necessarily linear.

```text
                         ┌──────────────┐
                         │    INPUT     │
                         │ Request      │
                         └──────┬───────┘
                                │
                                ▼
                     ┌────────────────────┐
                     │ Resolve eligibility │
                     └─────────┬──────────┘
                               │
                        eligibility state
                               │
                ┌──────────────┼──────────────┐
                │              │              │
                ▼              ▼              ▼
        ┌────────────┐  ┌────────────┐  ┌────────────┐
        │ ELIGIBLE   │  │ REVIEW     │  │ INELIGIBLE │
        └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
              │               │               │
              ▼               ▼               ▼
        ┌───────────┐   ┌───────────┐   ┌───────────┐
        │ Continue  │   │ Human     │   │ Produce   │
        │ processing│   │ approval  │   │ decision  │
        └─────┬─────┘   └─────┬─────┘   └─────┬─────┘
              │               │               │
              └───────────┬───┴───────────────┘
                          │
                          ▼
                  ┌───────────────┐
                  │  CONVERGENCE  │
                  │ admitted      │
                  │ disposition   │
                  └───────┬───────┘
                          │
                          ▼
                  ┌───────────────┐
                  │   OUTCOME     │
                  │ Decision is   │
                  │ established   │
                  └───────────────┘
```

The important thing is that the branch is **part of the graph authority**, not an invisible `if/else` buried in implementation code. The blueprint explicitly models branching, convergence, altitude descent, termination, and monotonic advancement as graph semantics. :chatgpt-content-reference{index="2"}

### 7. Multiple capabilities plugged into a semantic backplane

At estate altitude, the circuit gets really interesting:

```text
                 CAPABILITY DATA CENTER

 ┌─────────────────┐
 │ Capability A    │
 │ Identify User   │
 └────────┬────────┘
          │
          │ product:
          │ admitted-user
          ▼
 ┌─────────────────┐
 │ Capability B    │
 │ Resolve Credit  │
 └────────┬────────┘
          │
          │ product:
          │ credit-profile
          ▼
 ┌─────────────────┐
 │ Capability C    │
 │ Determine Terms │
 └────────┬────────┘
          │
          │ product:
          │ eligible-terms
          ▼
 ┌─────────────────┐
 │ Capability D    │
 │ Produce Offer   │
 └─────────────────┘
```

The connection isn't:

```text
A calls B
```

It is:

```text
Capability A
    │
    │ produces
    ▼
Product / Observable State
    │
    │ satisfies
    ▼
Capability B Input Contract
```

That's the **semantic backplane**. ADR-001 defines the Capability Data Center as an estate of sealed circuits connected through governed identities, contracts, products, routes, dependencies, interfaces, observability, and evidence obligations. :chatgpt-content-reference{index="4"}
